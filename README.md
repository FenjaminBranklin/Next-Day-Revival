# Next Day: Survival - Revival Toolkit

**The official master server for Next Day: Survival is gone.** The studio shut
it down, so pressing *Play* no longer gets anyone into the game. This project
brings it back: a private replacement master server, plus a one-click patcher
that points your game at it.

It also adds four new items, because once the server was running there was no
reason to stop.

---

## Just want to play?

1. **[Download the latest release](../../releases/latest)** and unpack it
   somewhere real (not inside the zip window).
2. Close the game. Double-click **`1_EINRICHTEN.bat`**.
3. Double-click **`2_SPIELEN.bat`**.
4. In the main menu: *Play*, then pick the server from the list.

That is all. No Python, no administrator rights, no BepInEx download - it is
in the package. Full details in `README_EN.txt` (English) or `LIESMICH.txt`
(German).

> **Do not use Steam's Play button.** It starts the EasyAntiCheat launcher,
> which refuses to run once the mod is installed. Use `2_SPIELEN.bat` - Steam
> itself still needs to be running.

Cloning the repository works too: it is spielfertig as it stands, the release
zip is just the same thing without the developer files.

## What the patcher does

`client_patch.ps1` is one call and idempotent - run it twice, nothing breaks.

| Step | |
|---|---|
| 1 | Finds the game (registry, Steam library folders, `-Game` as fallback) |
| 2 | Resolves the server address |
| 3 | Points `ClientConfig.ini` at the server list, backing up the old one |
| 4 | Disables EasyAntiCheat in the game code (8 bytes, size unchanged) |
| 5 | Installs BepInEx if none is present |
| 6 | Installs the plugin and its assets |
| 7 | Asks the server whether it is actually answering |

`-Check` reports all of that without touching a file. `-Restore` puts
`ClientConfig.ini` back.

**About step 4.** Exactly one method is changed: `ClientOptions::IsDisabledEAC`
returns a hard `true` instead of reading its backing field. The method header
and length stay, the body is padded with `nop`, so the file keeps its size and
every one of its other 15394 methods. The patcher refuses to touch the DLL
unless it recognises what it is looking at - a build it does not know is left
alone rather than guessed at.

## The mod

Four items, built from scratch - meshes, textures and icons are generated by
the Python scripts in this repository, not extracted from the game:

- **MG42** - 200-round belt
- **TAC-50** - bolt-action .50, with its own scope overlay
- **7.62 belt (200)** and **.50 BMG box (10)**

Plus a cursor and window fix for windowed mode.

## Building it yourself

```powershell
python make_assets.py          # meshes, textures, icons
powershell -File build.ps1     # compile and install
python verify.py               # static checks
powershell -File make_package.ps1   # build the release zip
```

`build.ps1` needs `csc.exe` from .NET Framework 3.5 (ships with Windows) and
a BepInEx-equipped installation to compile against. The plugin is C# 3.0 - no
optional arguments, no expression trees - because BepInEx 5.4 and HarmonyX
are CLR v2 assemblies.

**Close the game before building.** A running game holds the DLL open and
`csc` fails with `CS0016`, which looks like a compiler error and is not one.

## What is deliberately not here

No game code, no game assets. No `Assembly-CSharp.dll`, nothing from
`Managed\`, no extracted textures, no save files. The EAC change is *computed*
on your own installation at patch time rather than shipped as a modified file,
and the same principle applies throughout: this repository carries the method,
not the material.

The master server itself is a separate project and not published here.

Third-party components (BepInEx and the libraries it brings) are listed in
`DRITTANBIETER.txt` with their licences.
